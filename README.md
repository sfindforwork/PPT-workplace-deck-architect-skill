# Workplace Deck Architect

一个面向职场工作汇报、项目计划、产品方案和调研复盘的 Codex Skill。

它的核心目标不是把长文“做成好看的卡片”，而是把一份有层级、有事实、有逻辑关系的工作材料，拆解成一套容易理解、容易讲述、容易查找的 H5 演示页面。默认输出 H5；只有用户明确要求 PPT / PPTX / PowerPoint 时，才输出 PPT。

## 适用情况

适合以下任务：

- 根据项目计划书、产品方案、调研报告、述职材料或其他长文档制作 H5 演示稿
- 将已有 PPT 或 H5 重新组织、改版、视觉审查
- 把详细逐字稿、工作记录和案例拆解成清晰的页面结构
- 需要目录、章节封面、固定索引、页面跳转、高清图片查看或演讲者模式的演示页面
- 需要在不丢失重要事实的前提下，减少长文本的阅读负担

不适合仅仅制作营销落地页、品牌宣传页、海报，或只需要单页视觉设计的任务。此类任务应优先使用更匹配的设计或前端技能。

## 使用方式

将本目录放入 Codex 的 skills 目录后，在任务中使用：

```text
$workplace-deck-architect
```

也可以直接描述需求，例如：

```text
请使用 workplace-deck-architect，根据这份项目计划书生成一个 H5 页面。
保留原文的章节层级，但不要把页面做成论文目录；需要目录、章节封面和右侧详细索引。
```

建议同时提供：

- 原始长文档或逐字稿
- 明确的大纲和页数要求
- 已有 PPT / H5 或视觉参考
- 必须保留的图片、截图和素材路径
- 对输出格式、交互、演讲者模式的要求

## 核心方法

### 1. 先保留原文的逻辑骨架

文档中的 `1 → 1.1 → 1.1.1` 是内容结构和追溯关系，不应该原样变成每一页的主标题。Skill 会使用原有标题规划章节和页面，再将页面表达转换为章节名、可读的页面标题和稳定的导航。

### 2. 抽象表达，不抽空内容

把长句压缩成结构、流程、阶段、对比、证据或案例，但保留重要事实、约束、当前状态和关键例子。不凭空添加口号、升华句、指标或结论。

### 3. 组件服从信息关系

组件由内容关系决定：

- 串行关系使用编号路径、时间线或阶段轴
- 上升和成长关系必须通过位置或高度体现，不使用并列卡片掩盖进展
- 决策和异常关系使用流程图，并保留分支和兜底
- 并列分类使用统一网格或矩阵
- 对比使用对齐的比较表
- 没有量化数据的多项能力使用标注框架，不伪装成雷达图
- 截图和证据使用缩略图、画廊或可点击的高清查看

### 4. 建立职场演示的页面语法

根据材料需要组合封面、目录、章节封面、内容页、总结 / 规划页和致谢页。页面标题、页码、章节信息、索引位置、图片处理和背景系统应保持稳定；页面之间的区别来自信息角色，而不是随机换组件。

### 5. 索引按沟通任务选择

- 长篇、阅读型、内容密集型演示：使用左侧或右侧详细索引，展示完整章节名和页面标题
- 短篇、演讲型、低密度演示：可以使用安静的底部章节索引
- 有图片、流程图的一侧不适合放详细索引，应优先使用另一侧
- 右侧索引应是轻量页面导航，不做成不透明面板或贯穿全高的分割线
- 当前章节和当前页面分别高亮
- 封面、目录、结尾页通常隐藏索引；隐藏后必须回收索引预留的版心空间
- 索引不是流程图，不能用一条线穿过文字，也不能用随机交替色制造层级

### 6. 配色按语义分组

同一信息集合如果没有内部语义差异，应统一使用一种强调色。只有当颜色代表来源、角色、状态、阶段或其他真实区别时，才使用多种颜色。不要为了避免重复而机械地交替换色。

### 7. H5 交互要帮助理解

默认可使用章节跳转、键盘 / 滚轮翻页、轻量页面过渡、图片高清查看和可选的演讲者模式。动效应服务于页面关系，不使用漂浮装饰、自动播放大动画或广告式效果。

## 输出约定

- 默认生成可直接打开的本地 HTML H5
- 图片复制到 HTML 同级的独立资源目录
- 展示图片应支持点击查看高清大图
- 页面应保留源文档与页面的可追溯关系，但不把深层编号当作视觉主层级
- `（1）` 等显式页数标记应被视为页面预算，未经同意不拆页
- 交付前检查标题映射、内容完整性、对齐、密度、溢出、配色、索引跳转和图片查看

## 安装

将仓库克隆到 Codex 的 skills 目录：

```bash
git clone https://github.com/<your-account>/workplace-deck-architect.git \
  ~/.codex/skills/workplace-deck-architect
```

如果目录已经存在，可以直接替换为仓库内容，或将本仓库作为个人 skill 源码维护，再同步到 Codex skills 目录。

## 维护原则

只把可以迁移到其他职场演示任务的经验写入 Skill。具体项目的标题、配色、素材和页面文案留在项目文件中，不要污染通用规则。发现问题时，优先修正造成问题的结构或决策规则，而不是继续堆叠装饰组件。
